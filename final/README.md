# The heuristic we kept

xGT with a value-aware passer. β = 0.02, γ = 0.01, τ = 1.5.

```
h(city) = floor( -ln( xGT(city) ) / 0.01 + 0.5 )     h(goal) = 0
```

- the model: [`../core/xgt.py`](../core/xgt.py)
- the parameters, pinned in one place: [`method.py`](method.py)
- how it works: [`../docs/06_xgt_explained.md`](../docs/06_xgt_explained.md), and
  [`../docs/xgt_explained.pdf`](../docs/xgt_explained.pdf) at length
- why this one: [`../docs/05_why_xgt_won.md`](../docs/05_why_xgt_won.md)
- what it was measured against: [`results.md`](results.md), regenerated by `python experiment.py`

## How it scores

| | xGT | uniform-cost | straight-line | ring / min-edge |
|---|---|---|---|---|
| sanity pairs (test 2) | 8/8 | 0/8 | 6/8 | 4/8 |
| mean Spearman over 20 goals | 0.999 | – | 0.848 | 0.975 |
| weighted inversions | 0.000 | – | 0.083 | 0.001 |
| A\* optimal over 380 pairs | 380/380 | 380/380 | 380/380 | 380/380 |
| cities expanded, mean | 4.94 | 11.00 | 6.81 | 5.60 |

Zero inversions and a perfect rank correlation for goals Bucharest, Sibiu and Neamt;
0.996 for the worst of the twenty goals.

## Honest limits

It overestimates: `h` is 0 to 9 % above true remaining cost, so it is not admissible
and A\* carries no optimality guarantee. On this map it returned the optimal route
for every one of the 380 pairs anyway, and the same holds when the search is run
without re-opening closed nodes. That is a measurement on a 20-city graph, not a
proof.

The parameters were chosen on this map. On a different graph, re-run
`../experiments/01_expected_goal_threat/experiment.py` before trusting τ = 1.5.

## Where it runs in production

`ai-pathfinder-api`, `services/XgtHeuristic.java`: same formula, same constants
(β 0.02, γ 0.01, τ 1.5, initial 1e-3, clamp 1e-30, tolerance 1e-12, `floor(x + 0.5)`),
tables built once at class load and cached per goal. `services/AStarSearch.java`
consumes it.

`python tools/crosscheck.py` is what keeps that honest: it runs the Java ports in
`tools/java/` against the Python here and asserts the integer tables are identical,
city by city, for ten method/parameter combinations across four goals.
